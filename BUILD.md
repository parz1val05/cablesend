# Как получить рабочие файлы для теста

Собрать APK и приложение для Windows **внутри этой среды нельзя**: pub.dev, Flutter SDK,
Android SDK и Gradle закрыты политикой сети, а кросс-компилятора под Windows нет.
Поэтому сборка идёт в GitHub Actions — от вас не требуется ставить ни Flutter, ни NDK.

В репозитории лежит `.github/workflows/build.yml`. На каждый `push` он делает три вещи:

| Работа | Что даёт | Примерно |
|---|---|---|
| `check` | тесты ядра + **первая в истории компиляция Dart** (`flutter analyze`) | 3–5 мин |
| `android` | `cablesend-android-apk` — APK под три архитектуры | 10–15 мин |
| `windows` | `cablesend-windows` — папка с `cablesend_app.exe` и `cablesend.exe` | 8–12 мин |

Готовые файлы: вкладка **Actions** → нужный запуск → раздел **Artifacts**.

## Вариант 1: быстрее всего — подключите GitHub, и я всё сделаю сам

Откройте **Настройки → Коннекторы** в Claude и подключите GitHub
(ссылка, которую вернул сам GitHub: `https://claude.ai/customize/connectors?auth_start=github`).
После этого скажите мне — я сам создам репозиторий, залью код, запущу сборку, прочитаю
логи и исправлю ошибки компиляции. Вам останется скачать APK.

## Вариант 2: руками, если подключать коннектор не хотите

Создайте пустой репозиторий на GitHub, распакуйте присланный архив и выполните:

```bash
cd cablesend
git init
git add .
git commit -m "CableSend: ядро, приложение, сборка"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/cablesend.git
git push -u origin main
```

Сборка запустится сама. Если `check` упадёт — пришлите мне текст ошибки из лога,
это ровно те ошибки первой компиляции, о которых я предупреждал.

# Сценарий теста Android → ПК → Android

Нужны: компьютер с Windows, два Android-телефона, два USB-кабеля.
`adb` приложение ищет само в стандартных путях Android SDK — ставить его в PATH не нужно.
Если его нет совсем, поставьте **Android platform-tools** и распакуйте куда угодно.

**Подготовка телефонов.** На каждом: Настройки → О телефоне → 7 раз нажать «Номер сборки»,
затем Настройки → Для разработчиков → включить «Отладка по USB». При подключении кабеля
нажать «Разрешить» (лучше с галочкой «Всегда разрешать с этого компьютера»).

**Шаг 1. Телефон А → ПК.**
1. На ПК распакуйте `cablesend-windows` и запустите `cablesend_app.exe`.
2. Вкладка «Получить» → включите «Принимать файлы». С этого момента ПК сам держит
   USB-туннель для всех подключённых телефонов и переподнимает его при переподключении кабеля.
3. На телефоне А установите APK (`app-arm64-v8a-release.apk` для почти любого современного
   телефона) и откройте приложение.
4. На телефоне: вкладка «Отправить» → выберите файлы → в списке устройств должен появиться
   **«Компьютер»** → отправьте.
5. На ПК подтвердите приём. Файлы лягут в `…\Downloads\CableSend`.

**Шаг 2. ПК → телефон Б.**
1. Подключите телефон Б, откройте на нём приложение, вкладка «Получить» → включите
   «Принимать файлы».
2. На ПК: вкладка «Отправить» → выберите те же файлы → в списке появится
   **«Android (серийный номер)»** → отправьте.
3. На телефоне Б подтвердите приём.

Это и есть цепочка Android → ПК → Android, в два шага через ПК. Прямой передачи
«телефон в телефон одним действием» пока нет: это отдельная функция (ПК как ретранслятор),
её в коде нет. Скажите, если нужна именно она — добавлю.

## Что проверять в первую очередь
- Файл дошёл целиком: сверьте размер и, если файл важный, контрольную сумму.
  Ядро само считает SHA-256 и не переименует файл из `.part`, пока сумма не совпадёт.
- Отключите кабель и подключите снова: телефон должен снова увидеть «Компьютер»
  в течение ~3 секунд.
- Нажмите «Отклонить» на запросе — передача должна прекратиться без мусора в папке.
- Сверните приложение на телефоне во время приёма: должно остаться уведомление, и приём
  не должен прерваться.

## Чего в этой сборке заведомо нет
- **Шифрования и проверки, кто на другом конце.** Защищает только ручное подтверждение.
  Для теста в пределах своего стола это нормально, для реального использования — нет.
- **Приём на iPhone** требует открытого приложения; отправка с iPhone на ПК по USB
  невозможна в принципе (ограничение iOS).
- На Android 15 фоновый сервис приёма система останавливает примерно через 6 часов.
