# CableSend — Flutter-интерфейс

Три вкладки:
- **Отправить** — три шага: файлы → устройство → отправка.
- **Получить** — переключатель приёма, имя устройства, папка, журнал передач.
- **Кабели** — что подключено и как подключить. Содержимое зависит от устройства:
  на компьютере — Ethernet/Thunderbolt, Android и iPhone; на телефоне — кабель к
  компьютеру и USB-Ethernet.

## Запуск на компьютере
Нужен Flutter 3.47.7 или новее: этого требует `desktop_drop` 0.9 (более старые версии плагина не собираются под Android).
```
cd app
flutter create --platforms=windows,macos,linux,android,ios --project-name cablesend_app .   # создаст папки платформ, lib/ не трогает
flutter pub get
cargo build --release --manifest-path ../Cargo.toml                                          # ядро
export CABLESEND_BIN=$PWD/../target/release/cablesend                                        # Windows: set CABLESEND_BIN=...\cablesend.exe
flutter run -d linux        # или windows / macos
```
Если ядро не найдено, приложение запускается в **демо-режиме** с выдуманными устройствами
и баннером об этом сверху.

Для релиза положите `cablesend(.exe)` рядом с исполняемым файлом приложения.

## Запуск на телефоне
Ядро линкуется в приложение и вызывается через C ABI. Порядок сборки и шаги в Xcode —
в `../NATIVE.md`; Android-часть ставится скриптами `../tools/build_android.sh` и
`../tools/apply_android.sh`.

## Как это связано с ядром
`lib/backend/backend.dart` — интерфейс с тремя реализациями:

| Реализация | Где работает | Как говорит с ядром |
|---|---|---|
| `CliBackend` | Windows, macOS, Linux | запускает `cablesend … --json`, читает события построчно |
| `FfiBackend` | Android, iOS | `dart:ffi` → C ABI (`src/ffi.rs`), события забираются опросом |
| `DemoBackend` | везде, если ядра нет | выдуманные устройства и передачи |

Все три отдают одни и те же `BackendEvent` и `Peer`, поэтому экраны не знают, с чем работают.

Важная тонкость: `CliBackend` передаёт дочерним процессам `receive` и `peers` один и тот же
`--id`. Это разные процессы, и без общего идентификатора компьютер нашёл бы собственный
UDP-маяк и показал сам себя в списке устройств.
