# CableSend — кроссплатформенная передача файлов по кабелю

Цель: как LocalSend, но связь идёт **по кабелю** между любыми парами устройств (Windows, macOS, Linux, Android, iOS), без интернета, роутера и Wi‑Fi.

## 1. Ключевая идея
Любой кабельный канал сводится к **упорядоченному потоку байт**. Поэтому:

```
 Flutter UI (все ОС)
      │ flutter_rust_bridge (FFI)
 Rust-ядро:  протокол + передача + проверка SHA-256 + обнаружение
      │ trait Stream (Read+Write)
 ┌────┴───────────────┬───────────────────┬─────────────────────┐
 IP-кабель            ADB (Android)       usbmuxd (iOS)         (позже) AOA
 Ethernet/TB/USB4/    adb forward/reverse Apple Mobile Device   Android Open
 USB-тетеринг         → localhost TCP     Service / usbmuxd     Accessory
```
Протокол и логика передачи пишутся один раз; добавить новый кабель = добавить функцию, возвращающую поток.

## 2. Как подключать по каждой ОС и типу кабеля

| Пара устройств | Кабель | Транспорт | Что нужно |
|---|---|---|---|
| ПК ↔ ПК (любые ОС) | Ethernet (патч-корд, Auto-MDIX есть почти везде) | IP, link-local 169.254/16 или fe80:: | Windows/macOS выдают адрес сами. Linux: в NetworkManager метод «Link-Local» или `avahi-autoipd` |
| Mac ↔ Mac, ПК ↔ ПК | Thunderbolt 3/4, USB4 | IP поверх Thunderbolt | macOS: «Thunderbolt Bridge» автоматически. Linux: модуль `thunderbolt-net` (интерфейс `thunderbolt0`). Windows 11: USB4/Thunderbolt Networking на поддерживаемом железе |
| ПК ↔ Android | USB | **ADB**: `adb forward` (ПК→телефон), `adb reverse` (телефон→ПК) | На телефоне «Отладка по USB». Нужен `adb` (platform-tools) |
| ПК ↔ Android | USB | USB-тетеринг (RNDIS/NCM) → IP | Включить «USB-модем» на телефоне. Android 11+ часто поддерживает NCM |
| ПК ↔ iPhone/iPad | Lightning / USB-C | **usbmuxd** (туннель на TCP-порт приложения) | Windows: iTunes или Apple Devices (служба Apple Mobile Device). macOS: встроено. Linux: пакет `usbmuxd`. Устройство разблокировано и «Доверять». Приложение на iOS должно быть на переднем плане |
| ПК ↔ iPhone | USB | Personal Hotspot по USB → IP | Включить «Режим модема» |
| Телефон ↔ телефон (в т.ч. Android ↔ iOS) | Прямого кабеля нет | USB-Ethernet адаптеры + Ethernet-кабель (или коммутатор), оба как IP-клиенты | Поддержка USB-Ethernet в ОС телефона (iPadOS/iOS и Android поддерживают) |

Честные ограничения:
- iPhone ↔ iPhone и iPhone ↔ Android напрямую одним USB-кабелем **не соединяются**: ОС этого не разрешают. Решение — Ethernet-адаптеры (строка в таблице) либо ПК как посредник.
- Android ↔ Android по OTG возможен только через Android Open Accessory (AOA) — сложно, это этап 4.
- iOS нельзя держать в фоне как сервер: передача работает при открытом приложении.
- Экран телефона может блокировать доступ (запрос «Доверять»/«Разрешить отладку»): UI должен показывать подсказку.

## 3. Протокол (реализован в `src/proto.rs`, `src/transfer.rs`)
Кадр = `u32 BE длина` + UTF-8 текст с полями через `\t`.
1. Обе стороны: `HELLO <версия> <имя> <платформа>`.
2. Отправитель: `OFFER <n>` и n × `FILE <размер> <имя>`.
3. Получатель: `ACCEPT` или `REJECT` (пользователь подтверждает вручную).
4. Для каждого файла: сырые байты → `END <sha256>` → `OK` или `ERR <причина>`.

Защита уже в прототипе:
- имена очищаются от `../`, `C:\`, запрещённых в Windows символов, зарезервированных имён
  (`NUL`, `CON`, `COM1`…) и обрезаются по длине;
- запись идёт во временный `<имя>.part` рядом с целевым файлом, переименование — только после
  совпадения SHA-256; временное имя подбирается так, чтобы не затронуть уже существующий файл;
- лимиты на размер кадра и число файлов; конфликты имён → `name (1).ext`;
- таймауты на чтение и запись у отправителя, чтобы упавший получатель не подвешивал передачу.

## 4. Обнаружение
- IP-кабель: UDP-маяк (`CABLESEND2`, идентификатор устройства, имя, ОС, порт) на порту 53318 →
  TCP-сессия на 53317. Идентификатор нужен, чтобы устройство не находило само себя: свой же
  широковещательный пакет возвращается с собственного адреса. Он же убирает дубликаты, когда
  один маяк приходит сразу несколькими маршрутами.
- ADB / usbmuxd: обнаружение не нужно, устройства перечисляются самой системой (`adb devices`, usbmuxd LISTEN).

## 5. Что сделано в этом репозитории (прототип)
- `src/sha256.rs`, `proto.rs`, `transfer.rs`, `discovery.rs`, `transport.rs`, `main.rs`: CLI `cablesend` (`devices`, `receive`, `send`), только `std`, без внешних зависимостей.
- Проверено на этой машине: юнит-тесты (SHA-256 по эталонным векторам, имена, передача по loopback), два отдельных процесса, 50 МБ случайных данных, хеши совпали; поиск пира по маяку; отказ получателя не создаёт файлов.
- **Не проверено на железе**: ADB и usbmuxd (в среде нет ни `adb`, ни телефонов). Код usbmuxd написан по legacy-бинарному протоколу и требует проверки на реальных устройствах, особенно на Windows (TCP 127.0.0.1:27015).
- Не сделано: шифрование, IPv6, привязка к конкретному сетевому интерфейсу, проверка свободного
  места перед приёмом.
- `legacy/` — самый первый прототип на Python. В сборке не участвует, протокол и порты у него
  свои и несовместимые; подробности в `legacy/README.md`.

## 6. Безопасность (обязательно до релиза)
Прототип передаёт данные открытым текстом и без проверки личности пира; защищает только ручное подтверждение. До релиза:
- одноразовый PIN при сопряжении и шифрованный канал (TLS с закреплением сертификата, как в LocalSend, или Noise);
- ограничение интерфейсов (слушать только на кабельных интерфейсах и localhost для ADB/usbmuxd);
- лимит размера и свободное место на диске перед приёмом.

## 7. План разработки
1. **Ядро (сделано как прототип)** → заменить самописный SHA-256 на `sha2`, ввод-вывод на `tokio`, добавить TLS (`rustls`).
2. **Интерфейсы и IPv6**: перечисление адаптеров (`if-addrs`), маяк на каждый интерфейс, `ff02::1` для fe80::, mDNS (`mdns-sd`) как запасной вариант.
3. **Flutter UI + `flutter_rust_bridge`**: Windows/macOS/Linux — `.dll/.dylib/.so`; Android — `cargo-ndk` и foreground service; iOS — статическая библиотека. Экран: список подключённых кабелей и устройств, выбор файлов, перетаскивание, прогресс, подтверждение приёма.
4. **Android без отладки по USB**: AOA (Android Open Accessory) через `rusb`; встроенный клиент ADB (`adb_client`), чтобы не требовать platform-tools.
5. **Тесты на матрице устройств** (см. таблицу), автоподсказки по настройке кабеля в UI.

## 7a. Мост к Flutter
См. `NATIVE.md`: C ABI (`src/ffi.rs`) + `dart:ffi` для Android/iOS, консольная программа для настольных ОС.

## 8. Запуск прототипа
```
cargo build --release
cablesend receive --dir received --auto-accept          # на одном устройстве
cablesend peers                                        # кто рядом на кабеле
cablesend send file.zip --discover                      # на другом (Ethernet/Thunderbolt)
cablesend send file.zip --to 169.254.10.5:53317         # по адресу
cablesend devices                                       # Android (adb) и iOS (usbmuxd)
# графическая оболочка запускает receive и peers разными процессами, поэтому передаёт
# им один и тот же --id, иначе устройство увидит собственный маяк:
cablesend receive --id ABC & cablesend peers --id ABC
cablesend send file.zip --adb --remote-port 53317       # ПК → Android-приложение
cablesend receive --adb-reverse                         # Android-приложение → ПК (порт 53320 на телефоне ведёт к ПК)
cablesend send file.zip --ios --remote-port 53317       # ПК → iOS-приложение
```
